# Repository instructions

These rules govern the starter-kit source, not generated applications. Keep completed work on `main`. `origin` is the user's repository; `upstream` is `https://github.com/laravel/react-starter-kit.git`.

Read [README-maintainer.md](README-maintainer.md) for source setup, upstream synchronization, CI, installation testing, and publishing. Keep [README.md](README.md) focused on installed applications. Record active cleanup evidence in [CLEANUP-PLAN.md](docs/maintainer/CLEANUP-PLAN.md); preserve earlier decisions in the production audit.

## Safe source work

- Set `LARAVEL_INSTALLER_DEFER_HOOKS=1` for Composer installs/updates. Never run `composer setup` or explicit `install:features --answers` in source; explicit answers bypass deferral. Test installation only in disposable copies.
- Preserve Laravel installer compatibility: `chisel.php`, `chisel-paths.php`, Composer/Laravel hooks, and the `install:features` command remain in source.
- Only registration and account email verification are optional. Preserve their intentional Chisel regions, including nested/inline PHP, TypeScript, and JSX markers. Do not restore 2FA/passkey/password-confirmation installer branches. Those features and email-change verification always ship; retain runtime configuration behavior.
- Keep maintainer tests/support under `tests/Maintainer`, with `phpunit.maintainer.xml`. `phpstan.maintainer.neon` extends application analysis with installer files; `composer test:maintainer` runs both analysis and tests. Chisel removes maintainer tooling/docs and installs the application CI fixture. `README.md` and the small application test suite must survive.
- Do not commit generated lockfiles, `vendor`, `node_modules`, or Wayfinder helpers unless upstream adopts that convention. Preserve pre-existing changes; cleanup only artifacts generated by your work.

## UI invariants

- shadcn must report `base: base`, `style: base-nova`, preset `b37ZhrNTs`. Never introduce `radix-ui`, `@radix-ui/*`, `asChild`, or Sonner under application JS.
- Follow [focus and theme rules](docs/maintainer/focus-styles.md) exactly when changing UI. Keep solid 2px semantic focus outlines, component offsets, invalid/destructive states, and native forced-colors outlines. Avoid transitions that animate outline geometry/color.
- Keep one Tailwind/shadcn/Inter import set, Laravel `@source` directives, and `@fontsource-variable/inter` with matching Vite setup. Do not restore Instrument Sans/Bunny Fonts beside it.
- Preserve `FlashToaster`: confirmations use Base UI toasts; request failures use top-center `NotificationAlert`. Keep entrance/dismissal animations, countdown/pause behavior, reduced motion, focus restoration, and delayed loading feedback.
- Preserve shared dialog outside-click behavior, Escape/Cancel, confirmation expiry, and recovery-code clearing. Keep the local Inertia Form workaround until its documented removal conditions are met.
- Do not remove reusable components or alternate layouts merely because the default pages do not use them. Avoid appearance/functionality changes during cleanup.

## Validation and upstream changes

```bash
npx shadcn@latest info --json
php artisan wayfinder:generate --with-form --no-interaction
npm run build:ssr
composer run ci:check
composer run test:maintainer
npm run doctor
```

For installer changes, run both paths of `scripts/test-chisel.py` for all four selections, including archive/packaging and private maintainer-security checks. For UI/SSR changes, run the maintained browser suite against fresh generated apps and inspect rendered HTML, hydration, server/client errors, and visual behavior. Record unavailable real-device/deployment checks rather than claiming they passed.

Use the clean-tree/dated-backup/`--no-ff` upstream procedure in the maintainer guide, including its Radix regression scan after merging upstream. Keep that scan in the upstream-sync checklist only. Resolve conflicts by combining functionality with local customizations; never use bulk overwrites, directory-wide `--ours`, or an `ours` merge driver. For materially changed wrappers, use the installed shadcn and migrate-radix-to-base skills, preview individual changes with `--dry-run`/`--diff`, and maintain their exact `.migration` reports. Review intentional installer/marker differences against upstream before finishing.
